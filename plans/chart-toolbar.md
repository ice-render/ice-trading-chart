# 图表工具条（**已实现**，设计稿存档）

> 状态：**已落地**（2026-09-23 记录，同日三轮做完）。实现见 `src/toolbar.ts`（组件 +
> 三层定制）、`src/panes.ts` 的 `toolbar` / `setToolbar`（**占带**）、以及示例页
> `examples/terminal.html`（页面只留业务回调；`?toolbar=` 切三层定制的示例）。
> 下面保留**原始设计与取舍**（读它比读实现更快懂「为什么长这样」），落地时的修正与
> 三个待定项的定案在文末。
>
> 起因：对照币安合约页，那条工具条（周期 / 图表类型 / 指标 / 画线 / 显示）原来是
> **终端示例页自己画的**（`.chart-bar` + `.tb-menu`）。用户已明确：**它应该是图表的一部分，
> 但要允许使用方定制**。这份稿子定的是「怎么定制」，不是"要不要做"。

## 1. 放哪个包

**放 `ice-trading-chart`，`ice-chart` 一行不动。**

理由：默认项里除「周期」外全是交易语义（指标 = `indicators.ts`、画线 = `drawing.ts`、
显示 = 交易终端的画法）。`ice-chart` 的定位是通用图表库 —— 让它认识"画线工具""指标"
就破了本仓「交易语义收敛在交易层」这条边界（见 `AGENTS.md` 与 `orderBook.ts` 的定位说明）。

代价：纯 `ice-chart` 的使用者没有工具条。**这是刻意的** —— 通用图表不该替应用决定顶栏长什么样；
将来真要给通用场景，再在 `ice-chart` 里做**同一套接口的通用子集**（周期 / 类型 / 显示），
接口形状照抄这份稿子。

## 2. 定制方式：三层，按侵入度递增

三层覆盖三类使用方：**只想少放几项**、**想加自己的按钮**、**想整条自己画**。

### 第 1 层：声明式（覆盖大多数）

```ts
createTradingChart(target, {
  toolbar: {
    show: true,                       // 默认 true（这次用户定了"是图表的一部分"）
    position: 'top',                  // 'top' | 'bottom'
    items: ['intervals', 'type', 'indicators', 'drawings', 'display'],  // 顺序即显示顺序
    intervals: ['1m', '5m', '15m', '1H', '4H', '1D'],
    // 每一项还能细配，且**只覆盖给的字段**（其余走默认）
    overrides: {
      indicators: { label: '指标', collapsed: false },
      display: { items: ['log', 'percent', 'watermark'] },
    },
  },
});
```

要点：**`items` 只写名字，不写位置** —— 顺序由数组决定；不在数组里的项就是不显示。
这条比"给每项一堆 `showXxx: false`"更好维护，也省得每加一个内置项就多一个开关。

### 第 2 层：自定义项（不改库代码就能加按钮）

```ts
toolbar: {
  items: [
    'intervals',
    {                                   // 自定义项：与内置项同一个数组、同一套渲染
      id: 'alerts',
      label: '预警',
      icon: 'bell',                     // 内置图标名，或直接给 innerHTML（SVG 字符串）
      menu: (ctx) => buildAlertsPanel(ctx),   // 可选：点了弹面板（返回 HTMLElement）
      active: (ctx) => ctx.chart.getAlerts().length > 0,  // 可选：角标/高亮
      onClick: (ctx) => ctx.chart.openAlerts(),
    },
    'drawings',
  ],
}
```

**`ctx` 是这一层的核心**，它给的是"读写图表状态"的正规入口，而不是 DOM：

| 字段 | 用途 |
|---|---|
| `ctx.chart` | 图表实例（`setOption` / `toggleSeries` / `setDomain…`） |
| `ctx.stack` | 副图栈（`chartOf(paneId)` / `linkCharts`） |
| `ctx.indicators` | 当前指标状态（读）+ 开关方法（写） |
| `ctx.drawings` | 画线层（读工具 / 切工具） |
| `ctx.messages` / `ctx.theme` | 文案目录与主题 token（自定义项也用同一套，别自己写色值） |
| `ctx.refresh()` | 状态变了让工具条按签名刷新（不整段重建） |

同时定一条铁律：**工具条不自己存图状态**。周期、图表类型、指标显隐的真相永远是图表 option；
内置项只做"发意图 + 读状态"，所以外部 `setOption` 改了状态，工具条下一次刷新必须自己跟上
（这一条要有用例钉住，否则迟早出现"工具条显示 5m、图上是 1H"）。

### 第 3 层：整条替换（不留死角）

```ts
toolbar: { render: (ctx) => ({ element: myBar, update: (next) => { /* 按需刷新 */ } }) }
// 或
toolbar: { show: false }            // 完全不要；应用自绘，状态仍从 ctx 同源的公开 API 读
```

`render` 返回 `{ element, update }`：`element` 由应用塞进图表的布局槽位（位置/高度仍由图表算，
否则会盖住画布），`update(ctx)` 在状态变化时被调用 —— 与引擎"组件自带 update"的既有约定同形。

## 3. 与既有约定的一致性（照抄本仓已经跑通的那几套）

| 约定 | 从哪儿抄 | 工具条怎么做 |
|---|---|---|
| 样式注入一次 + 颜色走变量 | `orderBook.ts` 的 `--ice-book-*` | `--ice-toolbar-*`；色值全来自 `theme`，换肤一处改 |
| 文案走目录、不写死中文 | `messages.ts`（zh/en） | 内置项名与面板文案都进目录；自定义项的 label 由应用给 |
| 结构只建一次、变更按签名去重 | `orderBook.ts` / `Highlight` 的 `clipBox` | 激活态/角标按签名刷新，菜单面板只建一次 |
| 主题是一套 token | `theme.ts` | 工具条不引入新色值，只用 token |
| 组件只管呈现、交互回调给应用 | `orderBook` 的 `onPickPrice` | 自定义项的 `onClick(ctx)` 就是这条的延伸 |
| 公开 API 有中文 JSDoc 讲"为什么" | 全仓 | 同上；每层定制都写清"什么时候该用这层" |

## 4. 不做什么

- 不做**可拖拽 / 可保存布局**的工具条（那是另一个产品，不是图表库）；
- 不把账户、下单、资金、活动入口放进工具条（交易终端的业务面，越界）；
- 工具条**不进命中/事件热路径**：它只改 option，渲染仍走既有链路；不许为了它给画布加常驻覆盖层；
- 不新增第二套主题/文案机制（必须复用 `theme` 与 `messages`）。

## 5. 默认预设（对齐币安那条）

默认 `items` = `['intervals', 'type', 'indicators', 'drawings', 'display']`，
与币安那条的顺序一致；**页签（图表 / 信息 / 数据）不进工具条** —— 那是面板级切换，
留在宿主页（`terminal.html` 的 `.tabs`）。

## 6.5 删掉自绘那条之前，还差什么（2026-09-23 实测盘点）

"并存对照一轮再删"这一步**确实挡住了**：对照下来发现库当时**表达不了页面已有的四件事**，
直接删会丢功能。

| 自绘那条有什么 | 库当时能不能表达 | 现在 |
|---|---|---|
| 周期收藏按钮 + 五个菜单 | ✅ 能 | — |
| **指标参数输入框**（MA / EMA / BOLL / MACD 的周期） | ❌ 指标面板只有勾选 | ✅ 自定义面板（`menu`） |
| **语言 / 主题 / 配色方案**（选择型列表，不是开关） | ❌ `displayItems` 只有 on/off | ✅ 自定义面板 |
| **画线的删除 / 清空动作** | ❌ 同上 | ✅ 自定义面板 |

补的能力是**第 2 层的 `menu`**：`{ id, label, menu: (ctx) => HTMLElement }` ——
容器、定位、主题、点外部关闭都由库负责，**面板内容归应用**，且**每次打开时重建**
（这样参数框、语言列表都能按当前状态现建）。设计稿第 2 层原本就写了它，实现时只落了 `onClick`。

**已经做完**（2026-09-23 第三轮，同一批提交）：
1. 页面那五张菜单都改成了自定义面板（语言/主题/配色、指标参数、画线动作、周期收藏/自定义周期），
   行上的 `data-*` 与内置项共用一套命令路径（`setIntervalKey` / `setChartType` / …）；
2. 页面判断全搬进了具名方法（切周期**重订阅 K 线流**、参数改动重算指标、画线动作动 `drawing`），
   宿主回调只是这些方法的薄壳 —— 于是「左侧图标条」与「工具条菜单」走的是同一个 `setDrawingTool()`；
3. `.chart-bar` 里的自绘工具条（`.tb-menu` 那一套 HTML/CSS/JS）**已删**，只留页签
   `图表/信息/数据` 与右侧读数；工具条本体由库渲染，**占带**进 pane 栈顶部；
4. 三种定制**不另开示例页**（本仓只有一个示例页，见 `AGENTS.md`），改用查询参数：
   `?toolbar=simple`（第 1 层）/ `custom`（第 2 层，多一个「预警」自定义项）/ `replace`
   （第 3 层，整条自绘但位置仍由占带给）/ `none`（完全不要）。

⚠️ 落地时改掉的两处设计与一条踩到的坑：

- `items` 里的自定义项 **`label` 允许是函数**（`(ctx) => string`）：周期那种「按钮上的字
  跟着状态走」的项，不能只给固定串；按钮的 `title` 也跟着签名更新（换语言时悬停提示要换）。
- 第 2 层补了 **`ctx.closeMenu()`**：自定义面板的内容归应用，「点完要不要关」只有应用知道
  （指标多选要连着勾、选周期/选语言该关）。
- **占带插入之后必须重新求值每格的 option**：数值轴的档数按「绘图区高度 ÷ 一档最小像素」
  反推，只重排尺寸不重算，刻度会按带插入前那块更高的绘图区算 —— 一档当场挤到 17px。

## 7. 三个待定项（**已定案**，2026-09-23 落地）

1. **周期切换的语义**：工具条发"切到 5m"的意图后，是库自己去重启数据源，还是回调应用去切？
   本仓现在的做法是**应用负责**（示例页要重订阅）。我倾向：库只发 `onIntervalChange` 回调 +
   更新自己的 option，**不碰数据源** —— 因为库不知道数据从哪来。
   → **按这条落地**：`host.onIntervalChange` 里调页面的 `setIntervalKey()`，退订 / 重采样 /
   重订阅都在页面（示例页里是真的来回切 K 线 topic）。
2. **第 3 层要不要**：只做前两层也能"允许定制"，但会留下"想整条自己画"的使用方无处可去。
   我倾向保留（就是上面那个 `render` 契约）。
   → **保留了**，示例页 `?toolbar=replace` 跑的就是它；元素仍交给 `stack.setToolbar()`，
   所以「自己画」也不会盖住 K 线。
3. **`render` 的槽位**：工具条占的是图表布局之上的一条带（图表高度里扣），还是悬浮在画布上？
   币安是前者（占一条、不遮图）。我倾向**占带**：悬浮会挡住最上面那几根 K 线。
   → **按占带落地**：`PaneStackOptions.toolbar` / `PaneStack.setToolbar(slot)` —— 带占在容器
   顶部（或底部），pane 高度从容器高度里扣掉它；`refresh()` 顺带调 `slot.update()`，
   所以图表状态一变，工具条自己就跟上。
